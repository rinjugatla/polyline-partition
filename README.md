# polyline-partition

基礎矩形をポリライン（直線をつないだ折れ線）で区画に分割し、区画をランダムな色で塗り分けて表示する Web アプリです。公開ページ: <https://rinjugatla.github.io/polyline-partition/>

以下は、セットアップ方法と仕様書です。

## セットアップ

### 必要なもの

- Node.js（LTS）
- pnpm（`package.json` の `packageManager` に指定したバージョン。Corepack で有効にできる）
- Git

### 手順

```bash
git clone https://github.com/rinjugatla/polyline-partition.git
cd polyline-partition
corepack enable          # pnpm が未導入の場合
pnpm install             # 依存を導入（husky による Git フックも設定される）
pnpm exec playwright install chromium   # E2E テストを実行する場合のみ
pnpm dev                 # 開発サーバーを起動
```

`pnpm dev` の表示に従い、ブラウザで開発サーバーの URL（既定は `http://localhost:5173`）を開きます。

### コマンド

| コマンド | 内容 |
| --- | --- |
| `pnpm dev` | 開発サーバーを起動 |
| `pnpm build` | 静的サイトをビルド |
| `pnpm preview` | ビルド結果を確認 |
| `pnpm check` | 型検査（svelte-check） |
| `pnpm lint` | ESLint による検査 |
| `pnpm format` | Prettier による整形 |
| `pnpm test` | 単体テスト（Vitest） |
| `pnpm test:e2e` | E2E テスト（Playwright） |

### GitHub Pages へのデプロイ

`main` への push で GitHub Actions が動き、検査とテストが通ると公開されます。リポジトリ設定の Pages の Source は「GitHub Actions」にします。手元で本番相当のビルドを確認するときは、`BASE_PATH` を付けます。

```bash
BASE_PATH=/polyline-partition pnpm build   # PowerShell: $env:BASE_PATH='/polyline-partition'; pnpm build
pnpm preview
```

開発規約は `AGENTS.md` にまとめています。

## 仕様書

### 1. 概要・目的・スコープ

polyline-partition は、任意サイズの矩形（基礎矩形）を折れ線（ポリライン）で区画に分割し、区画ごとにランダムな色を付けて表示する Web アプリである。

目的は2つある。

- ポリラインによる矩形の分割結果を、視覚的に試せるツールとして提供する。
- 平面グラフの面抽出（交点計算、頂点併合、半辺構造、面列挙）を自前で実装し、アルゴリズムを学ぶ。

スコープ内:

- 基礎矩形の設定、ポリラインの描画と編集、区画分割の実行、区画の色分け表示、簡易統計、アプリ設定（ε とスナップ）の変更と保存
- JSON での保存・読込、SVG 出力

スコープ外（初期版）:

- モバイルとタッチ操作
- 曲線、閉じた図形（ポリゴン）の配置
- PNG 出力、分割結果の自動再計算
- UI の多言語対応（日本語のみ）
- 数百本を超える大規模入力向けの最適化

### 2. 用語定義

座標系は右手座標系（X 軸右向き、Y 軸上向き）で、基礎矩形は原点 (0, 0) から (W, H) までの領域とする。

| 用語 | 定義 |
| --- | --- |
| 基礎矩形 | 分割対象の矩形。幅 W、高さ H は人間が設定する（デフォルト 1000 × 1000）。境界を含む閉領域として扱う |
| 外側 | 基礎矩形（境界を含む）から距離 ε より離れた領域。境界上は外側に含めない |
| 頂点 | ポリラインの折れ点。座標 (x, y) を持つ |
| ポリライン | 2個以上の頂点を順に直線でつないだ線。曲線は含まない。自己交差は禁止。基礎矩形の内部を通らない線は不正として受け付けない（第4章） |
| 弦 | ポリラインのうち基礎矩形の内部を通る連続した部分。矩形境界から境界へ抜ける。1本のポリラインが矩形に複数回出入りすると複数の弦になる |
| 交点 | 異なる弦同士が基礎矩形の内部で出会う点。接触や頂点での出会いも含む |
| 区画 | 基礎矩形をポリラインで分割して得られる内部の面。穴を持たない単純な多角形 |
| ε（イプシロン） | 同値判定の許容誤差。デフォルトは 0.01 で、サイドパネルの「設定」から変更できる。幾何計算の関数には引数として渡す |
| 一般位置 | 3本以上の弦が1点で交わらず、線が重ならず、接触もしない配置。検算式が厳密に成り立つ条件 |
| 分割結果 | 区画の一覧、各区画の色、統計値をまとめたもの。編集により無効化される |
| ノーディング（noding） | 線分どうしの交点を求め、各線分を交点で小さな線分に分ける処理 |
| 頂点の併合 | 距離が ε 以内の点を1つの頂点にまとめる処理。計算誤差で生じる「ほぼ同じ点」を同一視する |
| 半辺（half-edge） | 1本の辺を、向きの異なる2本の矢印に分けたもの。各半辺は、自分の左側にある面に属する |
| twin と next | twin は半辺の逆向きの相方、next は面の境界を1周するときに次にたどる半辺 |
| 面列挙 | 半辺を next でたどって閉じた経路を集め、面を取り出す処理 |
| 符号付き面積 | 多角形の頂点を反時計回りにたどると正、時計回りにたどると負になる面積 |
| オイラーの公式 | 平面グラフで「頂点数 − 辺数 + 面数 = 1 + 連結成分数」が成り立つという関係。面数の検算に使う |
| Union-Find | 要素をグループにまとめる操作を高速に行うデータ構造。頂点の併合に使う |
| グリッドハッシュ | 平面を格子状に区切り、近くの格子にある点だけを調べて探索を速くする方法 |

### 3. 機能要件

機能は次の12項目で、ポリラインの検証ルールは第4章、画面操作は第5章、設定の保存は第6章に詳細を置く。

| ID | 機能 | 仕様 |
| --- | --- | --- |
| FR-01 | 基礎矩形の設定 | 幅と高さを個別に数値入力する（デフォルト 1000 × 1000、範囲 10〜10000）。範囲外の入力は拒否する。変更時は既存ポリラインを保持し、始終端が外側でなくなったものは無効として警告する |
| FR-02 | ポリライン描画 | 描画モードでクリックして頂点を追加し、ダブルクリックまたは Enter で確定、Esc で中止する。確定には2頂点以上が必要。本数に上限はなく、0本でもよい |
| FR-03 | ポリライン編集 | 選択、頂点のドラッグ移動、ポリラインの削除、全削除ができる。すべての編集操作は Undo / Redo の対象とし、ショートカットキーのほかに、サイドパネルの Undo ボタンと Redo ボタンからも実行できる。戻せる操作や進める操作がないときは、該当するボタンを無効にする |
| FR-04 | 入力検証 | 第4章の規則を、確定時と頂点の移動時に検査する。違反する操作は拒否し、理由を日本語で表示する |
| FR-05 | 区画分割 | 「区画分割」ボタンで実行する。ポリラインが0本でも実行でき、区画数は 1 になる。無効なポリラインがある間はボタンを無効にし、理由を表示する |
| FR-06 | 色付け | 区画ごとにランダムな色を付ける。色相は黄金角（約 137.5 度）ずつずらし、彩度と明度はシード付き乱数で揺らす。「色を再抽選」でシードを更新できる |
| FR-07 | 統計表示 | 常時表示は「ポリライン本数」と「区画数」。折りたたみ内に「弦数」「交点数」「検算結果」「破棄した微小面数」を表示する。分割前の区画数は「未分割」と表示する |
| FR-08 | 結果の無効化 | 頂点、ポリライン、矩形サイズ、ε のいずれかを編集すると分割結果を破棄し、塗りを消して「未分割」に戻す。自動再計算はしない |
| FR-09 | キャンバス操作 | 基礎矩形の周囲に余白を設ける。ホイールでズーム、中ボタンドラッグでパン、「全体表示」ボタンで初期位置に戻す。座標は ±100000 の範囲に制限する |
| FR-10 | スナップと軸拘束 | 頂点入力時のグリッドスナップ（デフォルト ON、刻み 10）。Shift を押している間は、基準の頂点から水平または垂直に拘束する。どちらも操作性のための機能で、ε による同値判定とは別のもの |
| FR-11 | 保存・出力 | JSON の保存と読込、SVG の出力。ファイル操作はブラウザのダウンロードとファイル選択で行う |
| FR-12 | アプリ設定 | サイドパネルの「設定」から、ε とスナップ（ON / OFF、刻み）を変更できる。値は localStorage に保存し、次回の起動でも保持する |

### 4. バリデーション規則

ポリラインは次の6つの規則をすべて満たすときだけ有効で、他のポリラインとの関係は規則の対象外とする。分割に寄与しないポリラインは不正として受け付けないので、面抽出の前に不要なポリラインを選別する後処理は要らない。

| ID | 規則 | 判定 |
| --- | --- | --- |
| V-01 | 頂点は2個以上 | 頂点数 ≥ 2 |
| V-02 | 長さ0の線分を作らない | 連続する2頂点の距離が ε 以下なら違反 |
| V-03 | 始点と終点は基礎矩形の外側 | 矩形までの距離が ε を超えること。距離は dx = max(−x, 0, x−W)、dy = max(−y, 0, y−H) として √(dx² + dy²) で求める。境界上は違反 |
| V-04 | 自己交差を作らない | 矩形の外側を含むポリライン全体で、隣接しない線分同士の交差、接触（距離 ε 以下）、共線の重なりを禁止する。隣接する線分は共有頂点でのみ接してよい。頂点で折り返して前の線分と重なる場合も違反 |
| V-05 | 座標範囲 | すべての頂点が x, y とも ±100000 以内 |
| V-06 | 基礎矩形の内部を通る | 矩形の内部（境界から距離 ε を超えて内側）を通る部分を、少なくとも1つ持つこと（弦数 ≥ 1）。矩形と全く交わらない線、角をかすめるだけの線、境界線上だけにある線は違反。境界に沿う部分と内部を通る部分の両方を持つ線は有効で、境界に沿う部分は辺として統合する |

他のポリラインとの関係は、交差、頂点での接触、共線での重なりをすべて許可する。重なった部分は1本の分割線として扱う。

判定のタイミングと違反時の挙動は次のとおり。

| 場面 | 検査する規則 | 違反時の挙動 |
| --- | --- | --- |
| 描画中の頂点追加 | V-02, V-04, V-05 | 頂点を追加せず、プレビュー線を赤で表示して理由を表示する |
| 描画の確定 | V-01, V-03, V-06 | 確定せず、理由を表示する。描画は継続できる |
| 頂点のドラッグ移動 | V-02〜V-05（移動中）、V-06（確定時） | 違反位置では確定せず、元の位置に戻す |
| 矩形サイズの変更 | V-03, V-06 | ポリラインを保持したまま「無効」として赤く表示する。無効なポリラインがある間は区画分割を実行できない |
| ε の変更 | V-02, V-03, V-04, V-06 | 矩形サイズの変更と同じく、無効になったポリラインを赤く表示し、区画分割を実行できなくする |
| JSON の読込 | V-01〜V-06 | 読込を中止し、違反内容を表示する |

### 5. 画面構成・操作仕様

画面は、左側のサイドパネルと右側の広いキャンバスの2領域で構成する単一ページとする（デスクトップのマウス操作が対象）。

キャンバスには次を表示する。

- 基礎矩形の枠と、その周囲の余白
- ポリライン（選択中は頂点ハンドルを表示。有効は通常色、選択中は強調色、無効は赤）
- 分割後は区画の塗りを矩形内に表示し、その上にポリラインを重ねる
- カーソル位置の論理座標（右手座標系の値）

サイドパネルは上から次の順に並べる。

1. 基礎矩形: 幅、高さの入力欄
2. ツール: 選択モードと描画モードの切替（起動時は描画モード）、Undo ボタン、Redo ボタン、全削除
3. ポリライン一覧: 各行に名前、頂点数、状態（有効または無効）、削除ボタン
4. 分割: 「区画分割」ボタン、「色を再抽選」ボタン
5. 統計: ポリライン本数、区画数、折りたたみの詳細
6. 保存・出力: JSON 保存、JSON 読込、SVG 出力
7. 設定: ε、スナップの ON / OFF、スナップの刻み

操作は次のとおり。

| 操作 | 入力 | 挙動 |
| --- | --- | --- |
| 頂点の追加 | 描画モードでクリック | スナップが ON なら格子点に吸着する。Shift を押している間は水平または垂直に拘束する |
| 描画の確定 | ダブルクリックまたは Enter | 確定時に末尾の重複頂点を取り除く（ダブルクリックによる二重追加の対策） |
| 描画の中止 | Esc | 描画中のポリラインを破棄する |
| ポリラインの選択 | 選択モードでクリック | 選択状態にして頂点ハンドルを表示する |
| 頂点の移動 | 頂点ハンドルをドラッグ | スナップが ON なら格子点に吸着する。Shift を押している間は水平または垂直に拘束する。違反位置では元に戻す |
| ポリラインの削除 | Delete キー、または一覧の削除ボタン | 選択中のポリラインを削除する |
| Undo / Redo | Ctrl + Z、Ctrl + Shift + Z、またはサイドパネルの Undo ボタン、Redo ボタン | 追加、確定、移動、削除、全削除、矩形サイズ変更を戻す、または進める。戻せる操作がないときは、該当するボタンを無効にする |
| ズーム | ホイール | カーソル位置を中心に拡大縮小する |
| パン | 中ボタンドラッグ | 表示位置を移動する |
| 区画分割 | 「区画分割」ボタン | 第7章のアルゴリズムを実行し、結果を表示する |
| 設定の変更 | サイドパネルの「設定」 | ε とスナップを変更し、localStorage に保存する（第6章） |

論理座標は右手座標系（Y 軸上向き）で保持し、画面描画の直前にだけ Y 軸を反転する。論理座標（アプリ内部で使う数学的な座標）と、スクリーン座標（画面上のピクセル位置）の変換は1か所の関数にまとめる。

Shift による軸拘束は、基準の頂点とカーソル位置の差を見て決める。x 方向の差の絶対値が y 方向の差以上なら水平（y を基準の頂点に合わせる）、そうでなければ垂直（x を合わせる）に拘束する。基準の頂点は、描画中は直前の頂点、頂点のドラッグ中は前の頂点（先頭の頂点では次の頂点）とする。最初の頂点には基準がないので拘束しない。拘束されない軸の座標には、スナップが ON ならグリッドスナップを適用する。

画面の部品は shadcn-svelte（Svelte 5 版の shadcn/ui）で組む。ボタン、入力欄、スイッチ、折りたたみなどの汎用部品は、`src/lib/components/ui` にある shadcn-svelte のコンポーネントをそのまま使う。クラスや関数のように役割を持つ専用のパーツは、1ファイル（`*.svelte`）に1つずつ切り出し、1つのファイルに複数の専用パーツを書かない。専用パーツの初期案は次のとおり。

- キャンバス: `Canvas.svelte`
- 基礎矩形の入力: `RectForm.svelte`
- ツール: `ToolPanel.svelte`
- ポリライン一覧: `PolylineList.svelte`
- 分割: `PartitionPanel.svelte`
- 統計: `StatsPanel.svelte`
- 保存・出力: `FilePanel.svelte`
- 設定: `SettingsPanel.svelte`

### 6. データモデル・保存形式

アプリの状態は、編集対象の「ドキュメント」、計算で得られる「分割結果」、ブラウザに保存する「アプリ設定」の3つに分ける。ドキュメントは JSON ファイルとして保存でき、分割結果は保存せず再計算する。アプリ設定は localStorage に保存する。

```ts
/** 論理座標（右手座標系、Y 軸上向き）の点 */
type Point = { x: number; y: number };

/** ポリライン。始点と終点は基礎矩形の外側に置く */
type Polyline = {
  /** ポリラインを識別する ID */
  id: string;
  /** 順につなぐ頂点（2個以上） */
  vertices: Point[];
};

/** 基礎矩形の大きさ。原点 (0, 0) から (width, height) までの領域 */
type RectSize = { width: number; height: number };

/** アプリ設定。localStorage に保存し、JSON ドキュメントには含めない */
type AppSettings = {
  /** 同値判定の許容誤差 ε */
  epsilon: number;
  snap: {
    /** グリッドスナップを有効にするか */
    enabled: boolean;
    /** 格子の刻み */
    step: number;
  };
};

/** 編集対象のドキュメント（JSON に保存する） */
type DocumentState = {
  schemaVersion: 1;
  rect: RectSize;
  polylines: Polyline[];
  /** 区画の色を決めるシード値 */
  colorSeed: number;
};

/** 分割で得られた区画 */
type Region = { id: number; polygon: Point[]; area: number; color: string };

/** 統計と検算の結果（保存しない） */
type PartitionStats = {
  polylineCount: number;
  regionCount: number;
  chordCount: number;
  intersectionCount: number;
  discardedFaceCount: number;
  checks: {
    euler: boolean;
    chordFormula: boolean | null; // 一般位置でないときは null
    areaSum: boolean;
  };
};

/** 分割結果（保存しない） */
type PartitionResult = { regions: Region[]; stats: PartitionStats };
```

JSON の例は次のとおり。

```json
{
  "schemaVersion": 1,
  "rect": { "width": 1000, "height": 1000 },
  "polylines": [
    {
      "id": "p1",
      "vertices": [
        { "x": -50, "y": 200 },
        { "x": 400, "y": 700 },
        { "x": 1100, "y": 300 }
      ]
    }
  ],
  "colorSeed": 12345
}
```

JSON の読込では、`schemaVersion` が 1 であること、型と数値範囲が正しいこと、第4章の V-01〜V-06 を満たすことを検査する。検査には現在の ε を使い、1つでも違反があれば読込を中止する。読込直後は「未分割」状態とし、同じ `colorSeed` で分割すれば同じ色になる。ε とスナップはドキュメントに含めないので、読込でアプリ設定は変わらない。

アプリ設定は、サイドパネルの「設定」から変更する。変更のたびに localStorage へ保存し、次回の起動時に読み込む。設定できる値と範囲は次のとおりで、範囲の数値は初期案とし、定数として1か所で定義する。

| 設定 | 既定値 | 範囲 |
| --- | --- | --- |
| ε（同値判定の許容誤差） | 0.01 | 0.0001〜1 |
| スナップ | ON | ON または OFF |
| スナップの刻み | 10 | 0.1〜1000 |

- 保存先のキーは `polyline-partition:settings` とし、値は `{ "schemaVersion": 1, "epsilon": 0.01, "snap": { "enabled": true, "step": 10 } }` の形の JSON とする
- 起動時の読込で値が不正だったり、localStorage が使えなかったりした場合は、既定値で動作を続け、設定欄に「保存できない」旨を表示する
- ε を変更すると、既存のポリラインを新しい ε で再検証し、無効になったものを赤く表示する。分割結果は無効化する（第4章）
- スナップの変更は、すでに置いた頂点には影響しない

SVG 出力の規則は次のとおり。

- `viewBox` は基礎矩形の範囲（`0 0 W H`）とし、矩形の外側は表示されない
- 論理座標のまま出力し、`transform="translate(0, H) scale(1, -1)"` で Y 軸を反転する
- 描画順は、矩形の枠、区画の `<polygon>`（分割済みのときだけ）、ポリラインの `<polyline>` とする
- ファイル名は `polyline-partition.svg` と `polyline-partition.json` とする

### 7. 面抽出アルゴリズム

基礎矩形の4辺とポリラインの線分を1つの平面グラフにまとめ、ノーディング、頂点併合、半辺構造、面列挙の順に処理して、内部の面を区画として数える。入力は有効なポリライン群と基礎矩形、出力は `PartitionResult` である。

処理手順は次の10段階である。

1. 線分の収集: すべてのポリラインの線分と、基礎矩形の4辺を集める。
2. ノーディング（交点計算）: 長さが ε 以下の線分は無視する。残りの全線分のペアを調べ、各線分上の分割点を求める。分割点は次の3種類で、線分に沿った順に並べて小線分に分ける。
   - 1点で交わる場合の交点
   - 一方の端点が他方の線分から距離 ε 以内にある場合の、その端点
   - 共線で重なる場合の、重なり区間の両端点（重なりがあったことを記録する）。重なりは、距離が ε を超えて離れた2点以上が互いの線分上にあるときに成立とし、端点1点だけの接触は重なりとしない
3. 矩形外の除去: 各小線分の中点が基礎矩形（境界を含む）から距離 ε を超えて外にあるものを捨てる。矩形の内部と境界上の小線分が残る。
4. 頂点の併合: 小線分の端点のうち距離 ε 以内のものを1つにまとめ、代表点に置き換える。セル幅 ε のグリッドハッシュで近傍9セルを探索し、Union-Find でクラスタにまとめる。代表点はクラスタ内で最初に登録された点とする。以降は頂点を ID で扱い、座標の比較はしない。両端が同じ頂点になった小線分は捨てる。辺に使われない頂点は残さず、頂点 ID は辺に最初に現れた順に振る。
5. 辺の確定: 頂点 ID の組を小さい順にそろえて辺とし、重複を取り除く。共線で重なった部分や、ポリラインと矩形境界が重なる部分は、ここで1本の辺になる。
6. 行き止まりの除去: 次数1の頂点とその辺を、なくなるまで繰り返し取り除く。弦は両端が矩形境界に届くため理論上は発生しないが、数値誤差への防御として行う。
7. 半辺構造の構築: 各辺を向きの異なる2本の半辺にして twin を結ぶ。各頂点から出る半辺を、`atan2` の角度が反時計回りになる順に並べる。半辺 h（u → v）の next は、頂点 v で twin(h)（v → u）の1つ手前、つまり時計回り側で隣の出半辺とする。この規則だと、面が常に半辺の左側に来る。
8. 面の列挙: 未訪問の半辺から next をたどって閉路を作る。各閉路の符号付き面積を靴ひも公式で求める。反時計回りの閉路は面積が正、時計回りは負になる。
9. 外周面と微小面の除去: 符号付き面積が負の閉路は、基礎矩形の外周を外側からたどったものなので除く。グラフは連結なので外周面は1つだけである。面積が ε² 未満の面は数値誤差による偽の面として破棄し、その数を記録する。
10. 色付けと統計: 区画を重心の y、x の順に並べて番号を振り、色と統計を決める。

色は次の規則で決める。i 番目の区画の色相は `(hue0 + i × 137.508) mod 360` とし、`hue0`、彩度（60〜75%）、明度（55〜70%）はシード付き乱数（mulberry32）で決める。区画の並びが決定的なので、同じシードと同じ入力なら同じ色になる。「色を再抽選」はシードを更新する。

ε を使う判定は次のとおりで、ε の値は設定（デフォルト 0.01）で変更でき、幾何計算の関数には引数として渡す。

| 判定 | 規則 |
| --- | --- |
| 点と点が同じ | 距離が ε 以下 |
| 点が線分上にある | 点から線分までの距離が ε 以下 |
| 2線分が共線 | 一方の両端点が、他方を含む直線から距離 ε 以内 |
| 2線分が交わる | 共線でなければ直線どうしの交点を求め、両方の線分から距離 ε 以内なら交点とする |
| 矩形の外側 | 基礎矩形までの距離が ε を超える |
| 微小面 | 面積が ε² 未満 |

統計の定義は次のとおり。

| 項目 | 定義 |
| --- | --- |
| ポリライン本数 | 配置した全ポリラインの数。有効なポリラインはすべて1本以上の弦を持つ |
| 区画数 | 抽出した内部の面の数（微小面を除く） |
| 弦数 | ポリラインに沿って並べた小線分のうち、矩形の内部にある連続した区間の数の合計。境界上の点に触れた場合はそこで区間を区切る |
| 交点数 | 矩形の内部で k 本（k ≥ 2）の弦が通る点それぞれの (k − 1) の合計。一般位置では交点の個数と一致する |
| 破棄した微小面数 | 手順9で破棄した面の数 |

結果の正しさは次の3つの検算で確かめ、結果を統計の詳細に表示する。

| 検算 | 式 | 成立条件 |
| --- | --- | --- |
| オイラーの公式 | 微小面を含む内部の面数 = E − V + 1（E は辺数、V は頂点数） | 常に成立（グラフが連結なため） |
| 弦・交点の式 | 区画数 = 1 + 弦数 + 交点数 | 共線の重なりがないとき。重なりがあれば検算せず null とする |
| 面積の総和 | 区画と微小面の面積の総和 = W × H | 差が ε × 2(W + H) 以内（併合による頂点のずれの上限） |

既知の制約は3つある。

- 頂点の併合の後に生じる新たな近接や交差は再検査しない。ε は座標の最大値（100000）に対して十分小さい前提とし、設定できる範囲を制限する（第6章）。
- ノーディングは線分数 n に対して O(n²) で、数百本、数千線分までを想定する。
- 共線や接触の判定式の細部は、実装時に境界条件のテストで固める。

### 8. テスト方針

テストは、ロジックを Vitest の単体テストで、画面を Playwright の E2E テストで確かめる2層とし、どちらも正常系、異常系、境界条件に分け、テスト名は日本語で書く。

命名は `describe`（対象）、`describe`（分類）、`it`（期待する動作）の3階層にそろえる。

```ts
describe('頂点の併合', () => {
  describe('正常系', () => {
    it('距離が ε 以内の2点を1つの頂点にまとめる', () => { /* ... */ });
  });
  describe('異常系', () => { /* ... */ });
  describe('境界条件', () => { /* ... */ });
});
```

#### 単体テスト（Vitest）

テストファイルは対象と同じディレクトリに `*.test.ts` として置く。対象は UI に依存しない `src/lib` 配下のロジックで、`src/lib/geometry` の行カバレッジ 90% 以上を目標にする。

| 対象 | 正常系 | 異常系 | 境界条件 |
| --- | --- | --- | --- |
| 幾何プリミティブ（距離、交差、面積） | 斜めに交差する線分の交点座標、符号付き面積の正負 | 長さ0の線分を扱う | 距離がちょうど ε、端点どうしの接触、共線の部分的な重なり |
| 座標の補正（グリッドスナップ、Shift の軸拘束） | 格子点に吸着する、Shift で水平または垂直に拘束する | 基準の頂点がないときは拘束しない | x と y の差の絶対値が等しいときは水平を優先する、刻みの下限と上限 |
| 入力検証（V-01〜V-06） | 有効なポリラインを受理する | 頂点1個、連続する同一頂点、始点が矩形内、自己交差、折り返し、座標範囲外、矩形と交わらない、角をかすめるだけ、境界線上だけを拒否する | 始点が矩形の境界上（違反）、境界から ε をわずかに超えた外側（有効）、隣接線分が共有頂点だけで接する、境界に沿う部分と内部を通る部分の両方を持つ線（有効） |
| ノーディング | 十字の交差で4つの小線分に分かれる、T字の接触 | 入力が空、長さ0の線分は無視する | 3本が1点で交わる、共線の重なり、端点が他方の線分上にある |
| 頂点の併合 | 近い点を1つにまとめる | 併合で潰れた線分を捨てる | 距離がちょうど ε、A-B と B-C が ε 以内で A-C は超える連鎖、グリッドのセル境界をまたぐ点 |
| 半辺構造・面列挙 | 正方形1つで内部1面と外周1面、格子状の面の数 | 行き止まりの辺を取り除く | 多数の弦が1点で交わる頂点、微小面の破棄 |
| 区画分割（全体） | 0本で1区画、十字で4区画、斜めの線1本で2区画、交差する複数本 | 無効なポリラインを含む入力は実行を拒否する | 矩形の境界に沿う部分を含む線、同じ線の重ね置き |
| 統計と検算 | 本数、区画数、弦数、交点数が期待どおり、3つの検算が成立 | 検算が不一致なら false を返す | 共線の重なりで弦・交点の式が null、矩形に複数回出入りするポリライン（弦数が本数より多い） |
| 色付け | 同じシードで同じ色、区画数と同じ個数の色 | 区画が0件なら空の配列 | 区画数1、シードが 0 と最大値 |
| JSON と SVG | 保存して読み込むと同じ状態、SVG の `<polygon>` が区画数と一致 | 不正な JSON、`schemaVersion` の不一致、V-01〜V-06 の違反を拒否する | ポリライン0本、分割前の SVG に `<polygon>` がない |
| アプリ設定の保存と読込 | 保存して読み込むと同じ値になる | 範囲外の値、不正な JSON、localStorage が使えない場合は既定値で動作を続ける | ε とスナップの刻みの下限値と上限値、保存データがないときは既定値 |

これに加えて、プロパティテスト（ランダムな入力に対して、常に成り立つべき性質を確かめるテスト）を行う。始点と終点を矩形の外側に置き、途中の頂点を乱数で決め、自己交差するものや矩形の内部を通らないものは棄却して生成する。確かめる性質は、区画の面積の総和と W × H の差が ε × 2(W + H) 以内であること、オイラーの検算が成立すること、一般位置のとき `1 + 弦数 + 交点数` が区画数に一致することの3つである。ライブラリは fast-check を使う。

#### E2E テスト（Playwright）

対象ブラウザは Chromium のみ、ビューポートはデスクトップサイズ（1280 × 800）とする。`webServer` でビルド済みのアプリを起動して実行する。ボタンは role と名前で、キャンバス、統計、区画は `data-testid` で特定する。マウス操作の座標は、全体表示を前提にした「論理座標から画面座標への変換」ヘルパーを `e2e/` に用意して指定する。

| ID | 分類 | シナリオ |
| --- | --- | --- |
| E2E-01 | 正常系 | 初期表示は 1000 × 1000、ポリライン 0 本、区画数は「未分割」 |
| E2E-02 | 正常系 | ポリラインが 0 本のまま分割すると区画数 1 になる |
| E2E-03 | 正常系 | 矩形の外から外へ抜ける線を1本描いて分割すると区画数 2、塗られた区画が2つ表示される |
| E2E-04 | 正常系 | 2本を十字に交差させて分割すると、ポリライン本数 2、区画数 4 になる |
| E2E-05 | 正常系 | 分割後にポリラインを編集すると、塗りが消えて「未分割」に戻る |
| E2E-06 | 正常系 | 「色を再抽選」で色が変わり、区画数は変わらない |
| E2E-07 | 正常系 | 描画後に Undo ボタンまたは Ctrl + Z で本数が戻り、Redo ボタンまたは Ctrl + Shift + Z で再び増える。履歴がないときはボタンが無効になる |
| E2E-08 | 正常系 | Shift を押しながら頂点を置くと、直前の頂点から水平または垂直の位置に置かれる |
| E2E-09 | 正常系 | JSON を保存して読み込むと同じ状態になり、SVG 出力で `<polygon>` が区画数と一致する |
| E2E-10 | 正常系 | 設定で ε とスナップの刻みを変更してページを再読み込みしても、値が保持される |
| E2E-11 | 異常系 | 始点が矩形の内部にあるポリラインは確定できず、エラーが表示される |
| E2E-12 | 異常系 | 自己交差になる頂点は追加できず、エラーが表示される |
| E2E-13 | 異常系 | 矩形を広げて始点が内側に入ったポリラインは無効と表示され、「区画分割」ボタンが無効になる |
| E2E-14 | 異常系 | 始点が境界のすぐ外にあるポリラインは、ε を大きくすると無効と表示され、「区画分割」ボタンが無効になる |
| E2E-15 | 異常系 | 矩形と交わらない線、角をかすめるだけの線、境界線上だけの線は、確定できずエラーが表示される |
| E2E-16 | 異常系 | 不正な JSON を読み込むとエラーが表示され、現在の状態は変わらない |
| E2E-17 | 異常系 | 範囲外の ε とスナップの刻みは設定できず、直前の値が保たれる |
| E2E-18 | 境界条件 | 幅と高さは 10 と 10000 を受け付け、範囲外の値は拒否する |
| E2E-19 | 境界条件 | 境界に沿う部分と内部を通る部分の両方を持つ線は確定でき、区画数が期待どおりになる |

- `vite.config.ts` の `sveltekit()` に adapter-static を渡し、`paths.base` は環境変数 `BASE_PATH` から取る。本番ビルドだけ `/polyline-partition` を渡し、開発時は空にする
- `static/.nojekyll` を置く
- GitHub Actions は `main` への push で動かす（PR では検証のみを行い、公開はしない）。先に `pnpm check`、`pnpm lint`、`pnpm test`、`pnpm test:e2e` を実行し、すべて通ったら `BASE_PATH` 付きでビルドして `deploy-pages` で公開する。E2E は `BASE_PATH` なしのビルドに対して実行する
- リポジトリ設定の Pages の Source は「GitHub Actions」にする

Claude Code での実装は、次の順に進めることを推奨する。

1. プロジェクトの雛形、shadcn-svelte の導入、husky（Git フック）、AGENTS.md と CLAUDE.md、Lint（規約を機械的に強制する設定）、テスト環境、CI
2. 幾何プリミティブと入力検証（テストを先に書く）
3. ノーディング
4. 頂点の併合
5. 半辺構造と面列挙
6. 分割パイプラインの統合とプロパティテスト
7. UI（キャンバス、描画、編集、Undo / Redo）
8. 統計、色付け、JSON と SVG
9. E2E テスト
10. GitHub Pages へのデプロイ

コーディング規約、Git と GitHub の運用ルール、テストの規約は `AGENTS.md` にまとめ、この仕様書とは分けて管理する。規約の詳細は `AGENTS.md` を正とする。Claude Code は `CLAUDE.md` を読み、`AGENTS.md` は直接読まないため、`CLAUDE.md` には `@AGENTS.md` の1行だけを書いて取り込む。

AI ツールは Claude Code 用の設定をリポジトリに含める。Svelte 公式 MCP（Svelte のドキュメント検索と、コードの誤りを自動検出する `svelte-autofixer`）を `.mcp.json` でローカル起動し、スキルは `commit`、`write-tests`、Playwright CLI の 3 つ、エージェントは `code-reviewer` と `spec-checker`（どちらも読み取り専用）を用いる。小規模なシステムのため、Svelte と TypeScript の専用エージェント・スキルは作らず、MCP、`AGENTS.md`、`svelte-check`、ESLint で足りる。詳細は `AGENTS.md` の 8 章を正とする。
