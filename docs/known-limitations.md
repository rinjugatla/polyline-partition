# 既知の制約と課題

polyline-partition の既知の制約と課題を、分野ごとに章を分けて記録する文書。仕様は `docs/spec.md` を正とし、この文書は仕様を補う。

## 幾何計算の既知の制約

手順2までの幾何計算（`src/lib/geometry`）で、問題が起きうる条件と、起きたときの挙動をまとめる。仕様書 7 章の「既知の制約」を補う。

要約:

- 想定する入力は人間の手動操作（グリッドスナップありの整数や少数の座標）で、浮動小数点の極端な配置は対象外とする。
- 20 万組のランダムな近似平行線分で測った範囲では、偽の交点は 0 件、V-04 の誤判定は 0 件だった。
- 起きうる問題は 3 つあり、いずれも「判定が一方に倒れて結果がずれる」だけで、例外やクラッシュにはならない。

### 1. 前提

- 浮動小数点数（小数を近似で表す数）の座標を `===` で比べない方針（`AGENTS.md` 4.6）に従い、同値判定は ε（イプシロン。「ほぼ同じ」とみなす許容誤差）を使う関数を通す。
- ただし、次の 3 か所は 0 との厳密比較を使う。いずれも 0 除算を避けるガードで、ε を受け取らない。

| 場所 | 比較 | 目的 |
| --- | --- | --- |
| `distancePointToSegment` | `lengthSquared === 0` | 長さ0の線分での 0 除算を避ける |
| `findSegmentIntersection` | `cross === 0` | 平行な線分での 0 除算を避ける |
| `passesThroughRectInterior` | `dx === 0 && dy === 0`、`direction === 0` | 長さ0の線分と、矩形の辺に平行な線分での 0 除算を避ける |

### 2. 問題が起きる条件と挙動

#### 2.1 ほぼ平行な線分の交点（`findSegmentIntersection`）

- 条件: 2 本の線分が完全には平行でないが、向きの差が極端に小さい（`cross` が 0 でないごく小さい値になる）。
- 挙動: 解 t、u（各線分上の位置）が大きな誤差を含みうる。ただし t、u が 0〜1 の範囲に入った解だけを交点として返すので、返された交点は実際に線分上にある。
- 測定結果（整数座標、向きの差が約 1e-5 rad、20 万組）:
  - 偽の交点（実際は交わらないのに交点を返す）は 0 件。
  - 取りこぼし（実際は交わるのに null を返す）は 6 件。いずれも完全に平行な共線の重なりで、仕様どおり null を返す設計である。
- 影響: `segmentDistance` は端点どうしの距離で補うため、取りこぼしても 0 を返し、V-04（自己交差の禁止）の判定は正しかった。

#### 2.1.1 回避策の案: 0 ではなく、ごく小さい実数と比べる

`=== 0` の代わりに、`< 0.000001` のようなごく小さい実数と比べて「平行」とみなす案がある。現時点では採用していない。

- 採用しない理由（推論）:
  - `cross`（2 本の向きベクトルの外積）は線分の長さの積に比例する。固定値だと、短い線分は角度が大きくても「平行」と判定され、長い線分はほぼ平行でも判定をすり抜ける。例えば長さ 0.02 の線分どうしでは、角度が約 2.5e-3 rad でも `cross` が 1e-6 を下回る。
  - 平行と判定された組は null になる。`segmentDistance` は端点距離で補うので距離の判定は保てるが、手順3のノーディングでは交点の座標が必要になる。
  - 固定値は、ε を設定で変わる値として引数で渡す方針（`AGENTS.md` 4.5）と合わない。
  - 0 除算の回避が目的なら、`=== 0` で足りる。0 でない小さい値での除算はクラッシュせず、誤差は範囲検査（t、u が 0〜1）で除かれる。測定では偽の交点が 0 件だった。
- 採用する場合の形:
  - `cross / (|d1| × |d2|)`（= sin θ。線分の長さに依存しない値）を、名前付き定数と比べる。定数は `src/lib/constants.ts` に置き、値の理由をコメントに書く。
  - 仕様書 7 章の「2線分が共線」は ε を使う規則として定義済みなので、手順3でその規則に合わせて入れるのが自然である。
- 判断: 手順2は現状のままとし、手順3で共線の扱いを決めるときに再検討する。

#### 2.2 測定していない条件

次の条件では、問題がないことを確かめていない。手動操作では通常起きないので、現時点では対処しない。

- 2 進数で正確に表せない座標（0.1 刻みなど）の近似平行線分。厳密な比較対象を作れていない。
- 向きの差が 1e-5 rad より小さい、さらに極端な配置。
- 座標が ±100000 に近く、ε が下限（0.0001）に近い組み合わせ。座標の桁数に対して ε が小さく、判定が計算誤差に埋もれうる。

これらで誤判定が起きた場合の挙動は次のとおり。

| 起きうること | 挙動 | 利用者から見えるもの |
| --- | --- | --- |
| 自己交差を見逃す（V-04） | 不正なポリラインを受理する | 後続の面抽出（手順3以降）で、区画数が期待とずれる可能性がある |
| 自己交差を誤検出する（V-04） | 有効なポリラインを拒否する | 頂点を置けず、自己交差の理由が表示される |
| 矩形の内部判定を誤る（V-06） | 角すれすれの線を受理または拒否する | 確定できない、または区画に寄与しない線ができる |

#### 2.3 頂点の併合後の再検査をしない

- 条件: 手順4（頂点の併合）で、ε 以内の点を 1 つにまとめた結果、新たに近接や交差が生じる。
- 挙動: 再検査しない（仕様書 7 章の既知の制約）。
- 影響: ε を座標の最大値に対して十分小さく保つ前提で、設定できる範囲を 0.0001〜1 に制限している。

#### 2.4 短い線分が長い線分を貫くときの共線判定（ノーディング）

- 条件: 長さが ε の 2 倍程度以下の短い線分が、長い線分を直角や斜めに貫く。仕様書 7 章の共線の定義（一方の両端点が他方の直線から ε 以内）に当てはまる。
- 挙動: 共線として扱われ、交点ではなく短い線分の両端点で長い線分が分かれる。共線の重なりも記録され、弦・交点の検算（`chordFormula`）が null になる。
- 影響: 検算が省かれるだけで、分割結果は変わらない。長い線分に ε 程度の短い小線分ができるが、手順4の頂点の併合で吸収する。

#### 2.5 同じ線分の重複

- 条件: 同じ線分が 2 回入る（同じ線を重ね置きしたポリラインなど）。
- 挙動: ノーディングは同じ小線分を 2 本出力する。重なりは記録される。
- 影響: 辺の確定（7 章の手順 5）で重複を取り除くので、設計上は問題ない。手順 5 で確かめる。

#### 2.6 線分数が多いとき

- 条件: 線分が数千本を超える。
- 挙動: ノーディングは全ペアを調べるので計算量が線分数の 2 乗になる。ペアごとに配列を確保するため、千本規模で遅くなる可能性がある（未測定）。
- 影響: 手動操作の規模（数十〜数百本）では問題ない。仕様書 7 章に同じ制約がある。必要になった時点で、外接矩形による除外を検討する。

### 3. 起きたときの対処

- 面抽出後の検算（オイラーの公式、面積の総和）が不一致になれば、判定のずれを検出できる（手順6で実装予定）。
- 再現する入力が見つかったら、先に再現するテストを追加し、そのうえで判定を直す（`AGENTS.md` 5 章）。
- 厳密さが必要になった場合は、固定シードのプロパティテスト（fast-check。ランダムな入力で常に成り立つ性質を確かめるテスト）として恒久化する。手順6で予定している範囲に含める案がある。

### 4. 方針の根拠

- このシステムは手動操作が前提で、スナップが既定で ON（刻み 10）なので、座標は粗い格子上に載ることが多い。
- 極端な配置に備えた厳密な幾何計算（有理数や適応的精度）は、YAGNI（必要になるまで作らない）に反するため入れない。
